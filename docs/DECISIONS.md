| D35 | 2026-11-01 | Vision review fixes. (1) A node claims its submit atomically before `createTask`; a node found claimed with no task id is never submitted again, and a create call that fails in a way that may follow an accepted task (network, 5xx, unreadable reply) ends the step as `submit_unknown` instead of retrying. (2) A step whose task exists but whose outcome is unknown (poll timeout, YouCam unreachable past the give-up time, result not downloadable) keeps its units counted as spent. (3) Release runs on every non-submit exit; settling is claimed so two polls cannot zero a node's units. (4) A step that reads a previous step's image keys its cache on the bytes that image has now. (5) Runs that make preview images keep them and their YouCam tasks for a 10 minute review window so Save works; the person's own photos are deleted at once. (6) A deployment-wide daily unit cap (live default 400) joins the session cap, because a session cap alone resets with the cookie. (7) Runs and the cache keep only the fields MIRA reads (`Feature.retain`). (8) The session cookie lasts 180 days like the profile cookie, and a production build never falls back to the public mock secret. (9) Delete my profile finishes pending run cleanup, removes ledger entries and the task index, and keeps only the session's unit total so a delete cannot reset a cap | The review (four independent readers, findings confirmed by test where possible) found double-charge and leak paths, a cache that could skip re-measuring a fresh render, stored fields the privacy screen did not show, and a profile that became unreachable after a browser restart. All are the product promise, trust, and each now has a regression test | Resubmitting after an ambiguous error and reconciling later (YouCam documents no idempotency key, so a duplicate charge cannot be undone); releasing units on timeout (under-reports a task that finishes) |
